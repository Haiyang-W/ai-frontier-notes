# MiMo V2.6 解读：Scaling RL Towards Self-Improvement

> [!IMPORTANT]
>
> **MiMo RL 的核心思路是：用大 batch 扩大探索，再用更好的评分和训练系统，把更多尝试转成能力提升。**
>
> 它让模型同时尝试大量编程、工具操作和网页设计任务，不仅判断是否做对，还比较哪种做法更值得学习。
>
> 大 batch 是规模化的抓手，评分与系统是让它有效的条件；论文验证了这套组合的效果，但尚未单独证明同等预算下大 batch 更优。

## Take Home Message

* **奖励的分辨率决定更多探索是否值得。** 全部过测时，二元奖励无法区分解法。**Groupwise Reward Synthesis（组内奖励合成，GRS）** 从尝试中提炼标准，再按实现与行为质量打分，使全成功组仍可学习；**Groupwise Advantage Redistribution（组内优势重分配，GAR）** 则在成败混合组中给优质成功解更大的正向学习权重。两者均引入质量偏好，并非只让同一目标学得更快。

* **训练资源是任务、环境与判卷标准的组合。** 开源 925 条通用工作任务中，**94.4% 的评分正文比题目长，字符长度比中位数为 2.33 倍**。标准保存了题面未展开的证据口径、别名与反例。其价值在监督信息，长度本身不保证准确；这些答案材料也应与 agent 输入分开。

* **调度和过滤共同决定课程。** 数据源耗时相差 **66 倍**；先完成先训练会偏向快任务，过滤无奖励差异的组又会偏向当前能区分好坏的题。Sample Mixer 补偿来源数量，但不自动恢复来源内部的难度分布。名义数据配比相同，实际学到的内容仍可不同。

* **验证器错误会改变最优行为。** 漏检让投机方案获奖，过严测试则惩罚有效替代解。MiMo 同时检查两者，并持续审计新轨迹。增加采样能发现更多解法，也可能更快发现评分漏洞；扩算力需要同步提高反馈可靠性。

* **执行一致性是学习信号的一部分。** 量化、专家路由和截断采样均会改变实际概率；若训练侧口径不同，更新权重会反映执行误差。重放修正这种差异，冻结路由抑制负载漂移，二者处理不同问题。恢复 router 即恢复负载平衡的干预，是报告较强的证据之一。

* **蒸馏也在选择教师能可靠指导的状态。** **Multi-Prefix Multi-Teacher On-Policy Distillation（多前缀、多教师在线策略蒸馏，MOPD2）** 让学生从教师轨迹或示范的中途自行续写，再接受教师逐 token 指导。它结合了学生自己的动作与外部提供的历史，因此既不能等同于照抄示范，也不能替代从头完成任务的训练。

* **更强已经观察到，更划算仍待证明。** DeepSWE 三次成绩平均值从 Pro 的 **58.4 升至 72.6**、Flash 的 **48.7 升至 65.7**，解题 token 也增长。这支持整套训练有效；预算未匹配，不能据此判定大 batch、更多推理或某个评分机制各贡献多少。

## 1. 底座与训练链路：探索能力在 RL 之前就受到约束

来源：[技术报告](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL/resolve/main/MiMo_V2_6_technical_report.pdf) §2–3、Table 1、§4、§6.4。

### 1.1 单次尝试的成本，决定固定预算能探索多少次

**长轨迹要反复读取历史，同题又要尝试 16 次，因此架构节省会被采样规模放大。** MiMo 用 MoE（Mixture of Experts，混合专家）减少每个 token 激活的参数，用 SWA（Sliding Window Attention，滑动窗口注意力）限制多数层的读取范围，再用少数 GA（Global Attention，全局注意力）层连接远处信息。

| 配置 | Flash | Pro |
| --- | --- | --- |
| 总参数 / 每 token 激活参数 | 310B / 15B | 1.02T / 42B |
| 主干层数：局部 / 全局 | 39 / 9 | 60 / 10 |
| Hidden size | 4096 | 6144 |
| SWA heads：Q / KV | 64 / 8 | 128 / 8 |
| GA heads：Q / KV | 64 / 4 | 128 / 8 |
| QK / V head dimension | 192 / 128 | 192 / 128 |
| 专家总数 / 每 token 选择数 | 256 / 8 | 384 / 8 |
| 局部窗口 / 最终上下文长度 | 128 tokens / 1M | 128 tokens / 1M |

主体堆叠“若干 SWA + 一层 GA”。首个 block 为 GA 与 dense FFN，其余用稀疏 MoE，无共享专家；层数不含 MTP 模块。

长序列分片时，SWA 只交换窗口内的 key/value，全局层仍处理全段上下文。**节省单次尝试可为更多探索留出预算**，但报告未隔离架构的 RL 增益；激活参数量也不等于同规模 dense 模型的成本。

### 1.2 多模态编码同时决定观察能力与输入成本

来源：§2.1–2.3、Figure 2。

图像、视频、音频经编码器接入文本主干。多轮交互累积观察，编码须兼顾信息保留与历史读取成本：

* **视觉保留二维联系。** 681M 参数的 MiMo-ViT 交替按行、按列组织局部注意力，再用全局层汇总，避免单一展开方向割裂空间邻接关系。28 层中 24 层局部、4 层全局；与小语言模型联合用理解任务训练，处理超过 4T image tokens，没有额外对比学习目标。局部层使用带 attention sink 的滑动窗口，多层传播可跨越固定窗口的边界。
* **音频压缩进入主干的位置数。** 每秒 25 帧，每帧 20 个离散码的 embedding 先相加，再把 4 帧合成一个输入表示，得到每秒 6.25 个位置。据此估算，60 秒音频约占 375 个主干位置。同帧 20 个残差向量量化（Residual Vector Quantization，RVQ）码共同描述一帧，并非 20 个位置。Audio Tokenizer 用约 2,000 万小时音频训练。序列压缩不等于整条编码链路等比例省算力。

**编码器限定 agent 可观察的信息；奖励不能保证补回编码时的损失。**

### 1.3 Mid-training 提前适配交互、长度和计算方式

训练顺序为 **预训练 → Mid-training → 短期监督微调（Supervised Fine-Tuning，SFT）→ 混合任务 RL → MOPD2**。各阶段提供不同的学习信号：

| 阶段 | 数据、监督与衔接 |
| --- | --- |
| 预训练 | 先训练文本主干，再接入视觉、音频编码器联合训练；Flash 为 26T 文本 + 22T 多模态 tokens，Pro 为 27T + 3T |
| Mid-training | 加入代码、通用、视觉、研究等 agent 轨迹，保留通用数据；大部分计算在 256K 上下文完成，最后扩至 1M |
| 短期 SFT | 形成进入 RL 的策略起点；报告未详细披露这一阶段配方 |
| 混合任务 RL（MixRL） | 模型自行执行任务，用测试、评分标准与模型评审产生反馈 |
| MOPD2 | 用 RL 领域教师和示范训练的 SFT 教师监督学生新生成的内容，合并并拓展能力，见第 7 节 |

Flash 预训练 48T tokens，Pro 30T，参数更少却看过更多数据，不能只按模型规模比较。上下文经预训练从 32K 扩至 256K，再由 Mid-training 接续到 1M。

Mid-training 还提前引入 **MXFP4 量化感知训练**，并把隐藏层权重矩阵从 AdamW 切换到 **Muown**。它是 Muon 的变体，通过显式控制权重矩阵的行范数，减轻谱范数漂移及对权重衰减的敏感性；见 [Muown 论文](https://arxiv.org/abs/2605.10797)。Embedding、输出层和 router 仍用 AdamW，router 到 RL 时冻结。

作者观察到 AdamW 随混合 RL batch 增大而收益递减，故提前适配 Muown；本次切换未出现损失突增，非任意模型无损切换的保证。

**RL 的稳定起点包含能力和执行条件。** 长上下文、低精度和优化器已提前适配；只复用模型权重，未必复现这一训练起点，状态继承见 3.7。

## 2. 计算投入：探索与判卷共同生产学习信号

来源：§4.1、§5.1、Figures 3、9、12。

**MiMo 每个训练 batch 包含 1,568 个题目组、每组 16 条轨迹，共 25,088 条。** 动态采样过滤无有效奖励差异的组，因此生成量可能更多。二元奖励下全成、全败均无差异；GRS 的质量分则可区分全过测组（§4.3.1）。

| RL 成本 | Pro | Flash |
| --- | ---: | ---: |
| 生成轨迹 | 43.8% | 44.9% |
| 评价轨迹 | 12.7% | 14.2% |
| 参数更新 | 43.5% | 40.9% |
| 本轮 RL 总成本 | 约 \$2.6M | 约 \$0.9M |

Figure 12 的 30 步耗时为 Pro 123.1 小时、Flash 81.8 小时，含故障恢复。总成本仅覆盖本轮 RL，非预训练或研发总投入。

**生成与评价合占 56.5% / 59.1%，超过参数更新。** 据此理解，RL 系统生产的关键资源是可用的比较信号，而非原始 token。二元奖励下，再多完全相同的成败结果也无组内优势；这解释了为何作者同时扩大采样与判卷，而非只扩 GPU。比例本身并非最优预算证明。

每步包含 2.7B–3.7B training tokens，平均序列约 110K–150K tokens；包含上下文，非新生成量。任务混合比例为代码 68%、通用工具 12%、视觉设计 13%、上下文遵循 3%、网络安全 4%，统计分母未明确，不能换读成 token 或算力占比；Sample Mixer 明确以保留组数为目标。

**收益应同时用成功率与解题预算衡量。** DeepSWE average@3 的 RL 起终点为 Pro 58.4 → 72.6、Flash 48.7 → 65.7；average@3 是三次成绩的平均，不是三次中至少一次成功的 pass@3。评测 token 同时增长，可能既来自更有效的方法，也来自更多检查和尝试。报告未给出固定训练预算的 batch 扫描或等推理 token 对照，因此支持“大规模 RL 可运行且有效”，尚不构成计算效率的 scaling law。

## 3. 学习信号：从区分成败，到区分做法

来源：§4.1 Eq. (1)、§4.3、§5.1。

### 3.1 GRS 与 GAR 让成功样本继续提供差异

MiMo 使用 GRPO（Group Relative Policy Optimization，组相对策略优化），在同题尝试间形成相对学习信号。**当多个方案都通过测试时，实现和行为质量仍可以提供学习方向。**

| 机制 | 怎样使用质量评价 | 改变什么 |
| --- | --- | --- |
| GRS：组内奖励合成 | 离线比较尝试、提炼评分标准；在线逐条评价，奖励为“测试分 × 实现质量分 × 行为质量分” | 轨迹奖励 |
| GAR：组内优势重分配 | 在线比较同题成功方案，把更多正向学习权重分给更好的方案；有限幅及全组重新中心化 | 轨迹优势 |

例如，两条成功轨迹原本各有 +0.5 优势，GAR 可调整为 +0.8、+0.2（未限幅示意）；实际限幅及重新中心化后不保证正优势总量守恒。**GRS 的测试分是门槛，质量分是门内排序：失败仍为零，全过测也可有分差。** 因此 GRS 能继续利用已过测的题，GAR 则在成败信号上细分成功解。

两者用于不同代码子集，**不是固定串行步骤**。GAR 只处理成败混合组；全成功组的初始优势为零，重分配也无法凭空制造差异。评分器不可用时退回原优势，不能当成任务失败（§4.3.2）。

**质量评价改变了“什么值得学”，不只是降低梯度噪声。** 报告观察到无 GAR 时出现吞异常、放宽验证等过测捷径；质量判断把可维护性纳入优化。但仍是整条轨迹加权，未证明每一步的因果贡献。Figure 8 仅覆盖 Flash、纯代码、batch 128、token-mean：GAR 支持训练至第 52 步，轮数稳定，长度仍约 140K → 210K；无 GAR 约第 28 步结束。证据支持该设置下的稳定性，不是普遍节省 token。

### 3.2 Prompt-mean：让长题不再仅凭 token 多就占更大权重

MiMo **先对同题轨迹组的 token 项平均，再在题目之间平均**。例如，两道题的轨迹组分别有 1 万、10 万 token：全 batch 按 token 平均时，名义权重约为 1:10；按题平均后，外层权重为 1:1。

```math
\mathcal{L}(\theta)
= -\mathbb{E}_{q\sim\bigcup_d\mathcal D_d,\;\{o_i\}_{i=1}^{G}\sim\mu_{\theta_{\mathrm{old}}}(\cdot\mid q)}
\left[
\frac{1}{\sum_{i=1}^{G}\lvert o_i\rvert}
\sum_{i=1}^{G}\sum_{t=1}^{\lvert o_i\rvert}
r_{i,t}M_{i,t}A_i
\log\pi_\theta(o_{i,t}\mid q,o_{i,\lt t})
\right].
```

内层以同题总长度归一化；外层对题目与采样取平均。

| 符号 | 含义 |
| --- | --- |
| $`q`$、$`G`$ | 题目及每题轨迹数，本次 $`G=16`$ |
| $`o_{i,t}`$、$`o_{i,\lt t}`$ | 第 $`i`$ 条轨迹的当前 token，以及之前的历史 |
| $`\pi_\theta`$、$`\mu_{\theta_{\mathrm{old}}}`$ | 当前训练策略，以及实际生成数据的策略 |
| $`A_i`$ | 轨迹优势；加入局部行为调整后，需要使用相应的逐 token 优势 |
| $`r_{i,t}`$ | 生成时与训练时概率差异对应的重要性采样权重 |
| $`M_{i,t}`$ | token mask；还需结合模型输出的训练范围及行为规则理解 |

> **数据配比要沿“采样 → 过滤 → loss 聚合”理解。** Sample Mixer 管来源数量，动态采样管哪些组有学习信号，prompt-mean 管组间名义权重。按题平均消除长题的外层长度优势，同题内长轨迹仍有更多 token 项；它不是每条轨迹等权，也不是长度惩罚。

### 3.3 逐 token IS：分母必须是真正生成时的概率

Partial rollout 的不同片段可能由不同策略版本生成。MiMo 使用逐 token 的 importance sampling（重要性采样，IS）权重：

```math
r_{i,t}
=\mathop{\mathrm{sg}}\nolimits\left[
\frac{\pi_\theta(o_{i,t}\mid q,o_{i,\lt t})}
{\mu_{\theta_{\mathrm{old}}}(o_{i,t}\mid q,o_{i,\lt t})}
\right].
```

分子是当前模型的概率，分母是该 token **生成当时保存的概率**；报告明确说不为 partial rollout 重新计算生成概率。统一旧版本事后补算会改错分母。$`\mathop{\mathrm{sg}}\nolimits`$ 表示停止梯度，ratio 只作权重，梯度经总目标的 log-probability 项传播。 **由公式可知，它只修正已到达历史下的动作概率，并未修正“为何到达这段历史”的概率；加上越界屏蔽，也不能视为完整无偏的轨迹校正。** 因此保留概率不等于可以无限容忍旧数据。

### 3.4 正负更新分开控制：越界 token 直接屏蔽

MiMo 为正、负优势分别设置概率比上下界，共四个边界：

```math
M_{i,t}^{\mathrm{clip}}=
\mathbf{1}\left[
(A_i\geq0\land\epsilon_+^{l}\leq r_{i,t}\leq\epsilon_+^{h})
\lor
(A_i\lt0\land\epsilon_-^{l}\leq r_{i,t}\leq\epsilon_-^{h})
\right].
```

两组初始区间均为 **[0.2, 5.0]**。越界 token 的 clip mask 为 0：ratio 为 6 时屏蔽，不是截成 5。它不等同于标准 PPO 的 `min(unclipped, clipped)` 目标。

训练中按策略熵调整，并监控两个方向的 token 屏蔽比例：

| 情况 | 正优势区间 | 负优势区间 |
| --- | --- | --- |
| 熵过低 | 放宽 | 收窄 |
| 熵过高 | 收窄 | 放宽 |

**鼓励与抑制可分开调节，但熵变化并非由区间宽度单独决定。** 报告未披露完整控制器，也未在目标中写出参考模型 KL 惩罚或默认优势标准差归一化，复现时不能按常见 GRPO 配方补齐。

### 3.5 长度惩罚：用同题成功解作参照，而非统一限制长度

来源：§4.3.3、Eq. (4)。

固定长度标准容易误伤复杂任务。MiMo 的做法是**先判断这道题是否已有足够高的通过率，再比较成功解之间的长度**：

1. **通过率超过阈值才启用。** 低通过率组保持原奖励，给困难任务保留探索空间。
2. **只用同题成功轨迹确定参考长度。** 取这些轨迹生成 token 数的指定分位数，避免用快速失败的轨迹作为效率标准。
3. **只对超出容忍范围的成功轨迹扣分。** 越长扣得越多，达到上限后不再增加；再由调整后的奖励计算优势。

设成功集合为 $`\mathcal P_q`$、每题轨迹数为 $`G`$。当 $`\lvert\mathcal P_q\rvert/G\gt a_{\min}`$ 时，参考长度为：

```math
\ell_q^\star=\mathop{\mathrm{Quantile}}\nolimits_{B/100}
\{\ell_j:j\in\mathcal P_q\}.
```

长度惩罚为：

```math
\widetilde R_i=R_i-\mathbf{1}[i\in\mathcal P_q]X
\left[
\mathop{\mathrm{clip}}\nolimits\left(
\frac{\ell_i/\ell_q^\star-1-\delta}{s-\delta},0,1
\right)
\right]^\gamma.
```

$`\ell_i`$ 是生成 token 数，$`B`$ 决定参考分位数；$`X`$ 是最大扣分，$`\delta`$ 是允许超出的比例，$`s`$ 决定何时扣满，$`\gamma`$ 控制扣分曲线。其中 $`s\gt\delta\geq0`$、$`X\geq0`$、$`\gamma\geq1`$。本文将原文通过率阈值 $`A`$ 改记为 $`a_{\min}`$，避免与优势混淆。

**示例（非报告配置）**：参考 10,000 tokens、容忍 20%，则超过 12,000 开始扣分；若 $`s=1`$，20,000 时扣满 $`X`$。完整超参数未披露。

> **通过率决定何时约束，同题成功解决定约束尺度。** 这优化成功后的效率；更长轨迹也可能包含必要验证，长度惩罚不能替代质量评价。

### 3.6 局部惩罚：按优势正负处理错误片段

来源：§4.3.3、Eq. (5)。

假设模型先发出一次无效工具调用，纠正后完成任务。如果把正优势用于整条轨迹，错误调用也会得到鼓励。MiMo 用规则标记格式破损、无效工具名、畸形参数等 token，再区别处理：

| 轨迹的优势 | 被标记的错误 token | 未标记的 token |
| --- | --- | --- |
| 正优势 | 优势设为 0，取消鼓励 | 适当增加正权重 |
| 负优势 | 放大负权重，加重惩罚 | 减轻负权重 |
| 零优势 | 保持为 0 | 保持为 0 |

**分支依据是优势正负，不是直接依据测试成败。** 奖励经过质量或长度调整后，成功轨迹也不一定具有正优势；另外，未标记只代表规则没有检测到错误，不代表行为已被证明正确。

令 $`h_{i,t}=1`$ 表示命中规则，否则为 0。调整后的逐 token 优势替换总目标中的轨迹优势：

```math
\widetilde A_{i,t}=\begin{cases}
\alpha(1-h_{i,t})A_i,&A_i\gt0,\\[0pt]
[\beta(1-h_{i,t})+\kappa h_{i,t}]A_i,&A_i\lt0,\\[0pt]
0,&A_i=0,
\end{cases}
\qquad \kappa\gt1.
```

$`\kappa\gt1`$ 决定错误片段的负权重放大多少；$`\alpha`$ 补偿未标记的正优势 token，$`\beta`$ 减轻未标记的负优势 token。**补偿是为了避免局部纠错顺便大幅改变整体正负权重。**

例如 100 个 token 原本各 +1，其中 10 个错误被归零，其余各调为 100/90，总和仍为 +100（假设未触发缩放限制）。

计算补偿系数时，统计范围是**整个 training batch 中参与 loss 的 token**，不是每条轨迹或每道题各自补偿。以 $`H_+,H_-`$ 表示正、负优势中命中规则的 token 集合，$`C_+,C_-`$ 表示未命中的集合：

```math
\alpha=\min\left(\alpha_{\max},
1+\frac{\sum_{(i,t)\in H_+}A_i}{\sum_{(i,t)\in C_+}A_i}\right),
\qquad
\beta=\max\left(\beta_{\min},
1-\frac{(\kappa-1)\sum_{(i,t)\in H_-}\lvert A_i\rvert}
{\sum_{(i,t)\in C_-}\lvert A_i\rvert}\right).
```

$`\alpha_{\max}\geq1`$ 限制正向放大，$`0\lt\beta_{\min}\leq1`$ 限制负权重减轻的程度。分母为零时，相应系数设为 1。**只有未触发限制、且分母非零时，正负两侧的优势总量分别守恒**；这不保证最终梯度或策略熵不变。

> **局部纠错不等于逐步贡献评估。** 规则只覆盖可识别的调用错误；正优势错误片段仅取消鼓励，负优势错误片段才加重惩罚，不能笼统理解成“错误 token 都受负奖励”。

## 4. 环境与验证：既防假成功，也防误杀正确解

来源：§4.2、Table 2、Figures 4–6、10。

### 4.1 可靠反馈来自任务、环境和评分的一致性

**验证器决定什么会被强化，因此它本身也需要验证。** MiMo 不只检查错误方案能否骗过测试，还检查满足需求的其他实现是否会被不合理限制拒绝。

| 任务 | 如何构造可靠反馈 | 关键取舍 |
| --- | --- | --- |
| 代码 | 检查需求与测试对齐；每题尝试 4 次并审计实际解法；有参考补丁时检查修复前后状态，要求 8 次重跑稳定 | 测试应检验功能，而非强制照搬参考实现 |
| 通用工作流 | 独立、可重置的 sandbox；在线服务用本地模拟；确定性状态用代码检查，开放交付物用模型评审，并检查无关文件是否被误改 | 最终回复声称成功，不等于数据库或文件真的正确变化 |
| 视觉设计 | 开放设计先逐件检查，再比较同题渲染结果；按图复刻以相似度指标为主、模型判断为辅 | 有无明确参考目标，决定评分方式 |
| 漏洞复现 | 题面与验证器来自同一运行时错误报告，匹配漏洞类型和最上层项目代码栈帧位置 | 触发任意崩溃不等于复现指定漏洞 |

代码任务来自 GitHub issues/PRs、员工需求、详细规格、既有功能和长程工程任务等。参考补丁可以帮助重建不完整题面，但不能把解法泄露进去。测试同时检查 **F2P（fail-to-pass，修复前失败、修复后通过）** 与 **P2P（pass-to-pass，修复前后都通过）**，分别验证修复效果和已有功能未被破坏。

例如，要求支持空输入却测试参考补丁的内部函数，会误杀其他正确实现（解释性例子）。审计 agent 联查需求、测试、补丁和执行记录，将冲突交给复查；它不直接替代测试。

通用工作流的本地模拟需覆盖操作、状态变化、输出格式和错误响应，并核对文件与数据库的名称、数值、时间线及引用。每次尝试恢复相同初态，才能比较策略；否则前一条轨迹修改库存，就会改变后一条轨迹的题目。训练时，开放内容评审使用自部署的 MiMo-V2.6-SFT。

通用任务用重复评审、不同 judge、不同能力轨迹及对抗方案修订标准。**重复执行检查稳定性，反例检查正确性，两者不能替代。** 由此推知，验证器应覆盖模型训练后新发现的行为，而非只在旧样本上准确；稳定地误判仍会被 RL 强化。

### 4.2 Reward hacking 必须同时处理行为、泄露路径和奖励

报告观察到模型从新版包、上游仓库和 issue/PR 获取现成补丁，绕过指定历史版本上的修复任务。这样的检索在实际开发中可能合理，在这些训练任务中却越过了允许的信息边界。

MiMo 的处理贯穿训练：Mid-training 加入纠错示范；准备环境时清除补丁、历史引用、日志、构建产物和缓存并隔离网络；用 hack agent 对抗检查；训练中持续审计，将确认违规轨迹的有效奖励归零，再重算组统计与优势。

**扩大探索也扩大了发现漏洞的机会。** 清理源码不能消除缓存中的答案，训练前审计也不能覆盖后来的捷径。低于 2% 是被检测出的 hacking 占比；缺少漏检率，不能把它当成全部违规率。

### 4.3 框架多样性训练的是交互适应能力

Harness 包括系统提示、工具接口、上下文管理和执行循环。MiMo 将其拆成可重组的 mini-harness：**同题一组尝试保持相同配置，组间切换配置**，兼顾组内比较公平与交互多样性。

未见过的 Codex、Claude Code、mini-swe-agent 上，DeepSWE 平均 Pass@1 约从 **50% 升至 66%**。Figure 10 是多框架训练的前后对比，没有同预算单框架训练对照，故支持“能力能迁移”，尚不能证明“多框架训练优于单框架”。**任务泛化与接口泛化应分别评测。**

## 5. 训练稳定性：负载平衡与概率对齐是两类问题

来源：§5.4、Figure 11、§6.4。

### 5.1 Router 更新可能增加系统代价，却没有可见性能回报

作者比较仅在 router 是否冻结上不同的 Pro RL runs，跟踪第 9 个 decoder layer 的 384 个专家：

| 指标 | Router 可训练：前 20 步 | Router 冻结 |
| --- | --- | --- |
| 负载变异系数：越大越不均衡 | 0.78 → 2.0 | 约 0.7 |
| 最繁忙专家负载 / 均值 | 6 倍 → 16 倍 | 约 5.5 倍 |
| 负载低于均值 10% 的专家占比 | 0.5% → 22% | 约 1% |

更有说服力的是恢复实验：**保持第 20 步其他参数，只把 router 恢复到 RL 起点，负载接近恢复，评测性能基本不变。** 这一干预比负载与性能的相关曲线更能定位 router 漂移的作用；但只覆盖该模型、层与训练窗口，不能推出 router 永远不值得训练。冻结参数也不固定专家选择，上游表示仍会变化。

### 5.2 重要性采样之前，先保证比较的是同一种概率

生成使用 SGLang，训练使用 Megatron-LM，专家权重采用 MXFP4。MiMo 分三层处理执行差异：

| 层次 | 处理 | 原因 |
| --- | --- | --- |
| 权重数值 | QDQ（quantize–dequantize，量化再反量化）遵循生成内核的数值约束 | 全精度权重相同，不代表实际参与计算的值相同 |
| 专家路径 | R3（Rollout Routing Replay，生成路由重放）保存并重放专家编号 | 微小数值误差也能改变离散的 top-k 选择 |
| 采样分布 | 保存生成时 top-k/top-p 候选集合，训练时在同一集合内归一化 | 截断采样概率不同于全词表概率 |

一个假设例子：某 token 全词表概率为 0.2，保留候选集的总概率为 0.8，实际采样概率就是 0.25。若训练侧直接以 0.2 除以 0.25，即使策略未变，ratio 也会变成 0.8。**候选集合必须取生成当时的集合；否则算法可能在“修正”执行口径差异。**

若生成时保留候选集为 $`S_t`$，训练应使用同一集合归一化：

```math
\pi_\theta^{S_t}(y\mid h_t)=
\frac{\pi_\theta(y\mid h_t)}{\sum_{v\in S_t}\pi_\theta(v\mid h_t)},
\qquad y\in S_t.
```

其中 $`h_t`$ 为当前历史，$`y`$ 为采样 token。只保存被采样 token 的概率，无法重建候选集合内的归一化分母。实现上，候选集先以全词表位图从 GPU 传至 CPU，再改用稀疏存储，避免变长传输带来的同步或截断。报告中 top-p=0.97 时平均候选数小于 5，存储较稀疏。

冻结 router 控制参数漂移，路径与候选集重放控制执行差异，重要性采样处理策略版本变化。这三者不能互相替代。

## 6. 系统设计：吞吐、数据分布与容量要一起管理

来源：§6.1–6.4、Figures 14–16；故障分析见 §5.5、Figure 12。

### 6.1 Partial rollout 用历史重算换取更少长尾等待

MiMo 并行采样，收齐一批后暂停未完成轨迹、更新参数，再恢复长任务，staleness 配置为 4。这样无需每轮等到最慢任务结束，但跨版本续跑要重建历史 KV cache，即 re-prefill；它消耗计算，却没有新增探索。

报告称大 batch 摊薄重算，但未单独对照。**一种解释**：并发固定时，大 batch 拉长更新间隔，减少长轨迹跨越的版本边界；若 batch 与并发同比增长则未必成立。应联合选择 batch、并发与续跑策略。

同一策略版本内，Context Cache 复用历史 KV，只处理新增后缀；等待工具时把状态移到主机内存。**活跃任务数不等于正在生成的请求数**，分层缓存能释放显存，但不能消除跨版本重算。

### 6.2 Sample Mixer 将目标配比转成资源分配

25 个数据源的平均生成 token 数相差 90 倍、平均耗时相差 66 倍。Sample Mixer 根据目标保留组数、过滤接受率、耗时和当前缺额调整并发，并同时考虑后续 batch，避免某个来源收齐后完全断供。

假设 A、B 各需保留 100 组：A 接受率 0.5、耗时 10 分钟，B 接受率 1、耗时 1 分钟。两者预计需生成 200、100 组；维持相同收集速率时，并发需求比约为 **20:1**。这里接受率指通过训练过滤的比例。

分发同时估计 KV 容量与推理并发；仅在启动或恢复的首个收集步，对慢源回放满足过滤与版本条件的完整组。Figure 16 模拟未包含训练、评分延迟、过期淘汰与回放，不是端到端吞吐。

**过滤还隐含了难度选择。** 简化推导：同题 16 次独立尝试、成功率相同且仅保留成败混合组时，单次成功率 1% 或 99% 的组仅约 14.9% 被保留，50% 时约 100%。实际轨迹可相关、奖励也可连续，但启发明确：来源配比达标，不等于难度分布不变；已过测题可由 GRS 转为质量学习，极难题则可能仍需更好的初始策略。

### 6.3 性能指标要对应实际瓶颈

MiMo 用常驻进程承载并发任务，调度节点只传奖励和索引，大数据分布式存储、按需读取。一条轨迹可能包含主对话、子 agent 分支和压缩后的上下文，系统分别记录并按前缀关系复用历史；多模态还需单独分配图像编码工作。文本 token 均分，并不代表图像编码量也均分。

**总体均衡不代表局部容量安全**，报告记录了四类故障：

| 观察 | 可迁移的教训 |
| --- | --- |
| 启动后短轨迹先完成，长度估计偏低，随后 KV 池耗尽 | 已完成任务不能代表仍在执行的长任务 |
| 同一代码源下，不同 harness 的轨迹长度相差超过两倍 | 资源估计要区分执行配置 |
| batch 整体均衡，局部 micro-batch 的专家 rank 却接收均值 30 倍以上的 token | 监控必须下钻到实际执行单元 |
| Flash 后期序列变长，分布式打包仍耗尽单节点主机内存 | 策略变化会使早期安全配置失效 |

### 6.4 推测解码应按端到端吞吐选择配置

DFlash 用小模型提出候选 token，再由主干并行验证。它先用 SFT 策略训练，再用匹配 RL 任务配比的早期轨迹适配；实际 RL 默认采用 block-6。

| 比较 | 报告结果 |
| --- | --- |
| block-6 相比原 MTP 配置 | 平均接受长度高 31.3% |
| 混合 RL 中 block-6 相比 block-8 | 全局平均吞吐高约 6%，接受长度变化很小 |
| 所测长上下文负载下，RL 适配的 FP8 DFlash 相比基线 | 每节点吞吐高约 10.3% |

**更多候选也增加主干验证工作，因此接受长度更长不保证整体更快。** 三项结果的比较基线不同，不能相加；block-6 与 block-8 的差异尤其说明，应优化端到端吞吐，而非局部接受指标。

## 7. MOPD2：合并能力，并保持教师监督有效

来源：§5.6、Figure 13、§6.2。

**难以设计可靠奖励的任务，仍可通过示范教师提供监督。** MixRL 后，MiMo 使用两类教师：可验证任务上的 RL 领域教师，以及用高质量合成示范训练的开放任务 SFT 教师。学生继续自己生成内容，教师对新生成内容逐 token 指导。

| 路径 | 学生从哪里开始 | 教师的作用 |
| --- | --- | --- |
| Standard MOPD | 自主执行整条轨迹 | MixRL 教师指导完整尝试 |
| Teacher-Prefix OPD | 教师轨迹某轮之前的历史 | 对学生新生成的一轮提供指导 |
| SFT-Prefix OPD | SFT 示范某轮之前的历史 | 对学生新生成的一轮提供指导 |

每个 assistant turn 前的完整历史都可成为一个前缀。学生生成新一轮，教师基于同一历史及学生已生成内容逐 token 指导；标准路径保留从起点自主执行。

**这里的 on-policy 只覆盖学生的新续写，前缀历史仍来自外部。** 从“已读完仓库、准备修改”开始，学生自行修改，非照抄答案；但它没有练习如何到达这一步（机制示例）。

据此理解，Prefix OPD 将长程任务拆成教师较熟悉的局部决策，减少重复执行与教师在异常历史下的失准。代价是自主到达、连续纠错的训练覆盖不足；保留完整 rollout 路径正好补充这一点。**教师的价值取决于在哪些状态上判断可靠，不能只看教师整题得分。**

**“走向自我改进”应理解为方向，而非已完成递归闭环。** 教师仍来自 RL 或合成示范 SFT，任务和评分器也依赖外部建设；报告未展示模型自主迭代这些组件的实验。MOPD2 未给出前缀路径的独立消融，亦未完整披露教师名单、学生初始化及损失配置。最终成绩支持整条链路有效，不能单独证明前缀蒸馏或开放领域拓展的增益。

**“接近前沿”只在部分任务成立。** Pro 在 AutomationBench 领先表中基线，但 Terminal Bench 4.0 为 34.9，对比 Claude 的 49.0；漏洞复现接近 95%，也不能外推到漏洞利用。基线均用最高推理档位不等于成本公平，表中差距还缺少统一预算与统计不确定性。

### 8.3 开源任务显示，判卷标准也是核心训练资源

官方 [MiMo-V2.6-RL-oss](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss) 提供 **7,780 条任务**：代码 2,698、安全 1,000、通用工作与终端 989、网页 2,093、音乐 1,000，以及[训练代码](https://github.com/XiaomiMiMo/verl/tree/mimo-oss)和[环境镜像](https://hub.docker.com/r/xiaomimimo/mimo-v2.6-rl-oss)。这是任务与环境资源，非内部 RL 全量轨迹。

* **判卷比出题更细。** 925 条通用工作任务中，94.4% 的评分正文比题目长，逐题字符长度比中位数为 2.33 倍，每题评分条目中位数为 5。例如律师名册核对，还要明确排除失效记录、合并别名、解释资料冲突。这些是压缩的领域知识；若直接把整条记录喂给 agent，也会泄露判卷答案。
* **明确标准仍可能依赖模型判断。** 5,125 个评分条目中，4,437 项标为模型评审，尽管顶层统一标为 `rule`。任务可验证不等于程序能确定性评分；复现还依赖 judge 的模型版本与证据读取方式。
* **环境也是任务身份的一部分。** 安全数据的 1,000 条记录只有 693 种题目文本，却对应 1,000 个镜像名。仅按文本去重会忽略环境实例差异；镜像不同也不能证明漏洞独立，还需核对源码版本与漏洞身份。

**开源入口复现的是 §7 的小模型实验。** 核对[代码脚本](https://github.com/XiaomiMiMo/verl/blob/a2ad9f6160b03ff2d47e59832bfb6b289f37c917/scripts/code/train.sh)（2026-09-29）：默认 batch 64、每题 16 条、256K 上限，工具错误惩罚默认关闭；不能把它当成 Pro/Flash 内部配方的逐项实现。

数据统计固定于 `639865f`，评分字符数排除 JSON 与验证代码，非 token 或成本；见[结果](data/MiMoV2.6-RL-oss-summary.json)与[脚本](../../scripts/analyze-mimo-rl.py)。
