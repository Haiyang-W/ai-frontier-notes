# MiMo V2.6 解读：大规模 RL 如何把探索转成有效学习

> [!IMPORTANT]
>
> **MiMo RL 的核心思路是：用大 batch 扩大探索，再用更好的评分和训练系统，把更多尝试转成能力提升。**
>
> 它让模型同时尝试大量编程、工具操作和网页设计任务，不仅判断是否做对，还比较哪种做法更值得学习 （更多的算力转向评分计算）。
>
> 大 batch 是规模化的抓手，评分与系统是让它有效的条件；论文验证了这套组合的效果，但尚未单独证明同等预算下大 batch 更优。

## Take Home Message

* **大 batch 提供更多尝试，评分决定哪些尝试值得学习。** MiMo 每个更新步使用 **1,568 道题 × 16 次尝试**。每次尝试都包含模型与工具交互的完整过程，称为一条轨迹。生成与评分合占 Pro / Flash 本轮强化学习（Reinforcement Learning，RL）成本的 **56.5% / 59.1%**；模型需要从这些轨迹中获得可信的差异，才能有效更新。

* **通过测试以后，模型仍可以学习更好的实现。** 对同题的一组尝试，**Groupwise Reward Synthesis（组内奖励合成，GRS）** 补充实现和行为评分，让全部通过测试的组也能产生质量差异。**Groupwise Advantage Redistribution（组内优势重分配，GAR）** 则用于成功、失败都有的组，把更多正向学习权重分给优质成功解。可维护性等要求因此进入了训练目标。

* **题库的比例，未必就是训练的比例。** 数据源平均耗时相差 **66 倍**，按完成顺序收集会偏向快题；过滤奖励完全相同的组，又会偏向当前能区分成败的题。因此，即使调度补齐了各来源的数量，来源内部的难度分布和训练权重仍可能改变。

* **训练和生成要在相同条件下比较概率。** 低精度量化、专家选择和采样范围，都会影响生成 token 的概率。MiMo 在训练侧重放生成时的专家路径与候选 token 集合，减少引擎差异对更新权重的干扰。专家路由器（router，负责选择专家）还影响计算负载：恢复实验表明，本次负载恶化没有带来可见的成绩提升。

* **前缀蒸馏练习单轮决策，完整轨迹练习从头完成任务。** **Multi-Prefix Multi-Teacher On-Policy Distillation（多前缀、多教师在线策略蒸馏，MOPD2）** 将教师轨迹或示范中某一轮之前的完整历史作为“前缀”，让学生只续写当前轮。这减少了多轮偏离导致教师指导失准的风险；完整轨迹训练则保留从头规划、执行和纠错的练习。

* **成绩提高了，还需在相同预算下比较。** DeepSWE 三次成绩平均值从 Pro 的 **58.4 升至 72.6**、Flash 的 **48.7 升至 65.7**，解题 token 也增加。报告未提供完整等预算对照，也没有展示模型自行改进任务、评分器和训练配方的过程。

## 1. 大 batch 的生成、评分与训练成本

一次 agent 任务会经历读文件、调用工具、修改、测试和纠错。同题采样更多轨迹，就要多执行这些过程，也要多做评分。MiMo 扩大 batch 的同时扩展评分和训练系统，目的就是让增加的尝试能够用于模型更新。

> **关键 insight：原始 token 不是最终的学习资源，可用的比较信号才是。** 同题尝试若奖励完全相同，组内相对更新就缺少方向。扩展评分，是把更多探索转成可用差异；成本占比本身不能证明预算分配最优。

### 1.2 从预训练到 RL 的训练流程

训练顺序是 **预训练 → Mid-training → 短期监督微调（Supervised Fine-Tuning，SFT）→ 混合任务 RL（MixRL）→ MOPD2**。

预训练建立文本和多模态能力；Mid-training 再加入 agent 轨迹，将上下文扩至 1M，并提前适配 MXFP4 低精度计算和 Muown 优化器。短期 SFT 得到 RL 的初始策略，随后 MixRL 根据任务执行结果训练。最后，MOPD2 用领域教师指导学生，合并并拓展能力。

RL 继承 SFT 的 FP32 主权重和 Muown 行状态。短期 SFT 的详细配方未披露，优化器配置见第 5.5 节。

预训练分为文本、多模态两个阶段：Flash 分别使用 26T + 22T tokens，Pro 为 27T + 3T。Flash 参数更少，却看过更多数据，比较两者时需要同时考虑训练数据量。上下文长度则在预训练中从 32K 扩至 256K，再由 Mid-training 扩至 1M。（来源：§2–3。）

### 1.3 架构如何降低长轨迹的成本

长轨迹需要反复读取历史，同题又采样 16 次，降低单次生成成本就有了更大价值。MoE（Mixture of Experts，混合专家）只为每个 token 激活部分专家，减少参与计算的参数。多数层采用 SWA（Sliding Window Attention，滑动窗口注意力），只读取附近的历史；少数 GA（Global Attention，全局注意力）层处理全局信息，保留跨长距离的联系。（来源：§2、Table 1、§6.4。）

<div align="center">

| 配置 | Flash | Pro |
| :---: | :---: | :---: |
| 总参数 / 每 token 激活参数 | 310B / 15B | 1.02T / 42B |
| 主干层数：局部 / 全局 | 39 / 9 | 60 / 10 |
| Hidden size | 4096 | 6144 |
| SWA heads：Q / KV | 64 / 8 | 128 / 8 |
| GA heads：Q / KV | 64 / 4 | 128 / 8 |
| QK / V head dimension | 192 / 128 | 192 / 128 |
| 专家总数 / 每 token 选择数 | 256 / 8 | 384 / 8 |
| 局部窗口 / 最终上下文长度 | 128 tokens / 1M | 128 tokens / 1M |

</div>

首个 block 使用 GA 和稠密前馈网络（dense FFN），其余使用稀疏 MoE，没有共享专家。表中层数不含多 token 预测（Multi-Token Prediction，MTP）模块。

长序列分到不同设备后，SWA 只需交换局部窗口内的 key / value，全局层仍处理全段上下文。因此，这种设计也能减少局部层的通信。但实际成本还包括注意力和通信等开销，不能仅用激活参数量换算成同规模稠密模型的成本。

多模态输入的编码方式也会影响上下文长度。681M 参数的 MiMo-ViT 有 24 层局部、4 层全局注意力，局部窗口交替按行、按列组织，再全局汇总。它与小语言模型联合用理解任务训练，处理超过 4T image tokens，无额外对比学习目标。

音频输入经过两步合并：每秒 25 帧，每帧先把 20 个残差向量量化（Residual Vector Quantization，RVQ）码的 embedding 相加，再将 4 帧合成一个主干输入。这样每秒占 6.25 个位置，按此估算，60 秒音频约占 375 个主干位置。每帧的 20 个码没有各自占一个位置；这里节省的是主干输入长度，整条编码链路未必等比例省算力。

> **关键 insight：降低单次生成的成本，可以给更多尝试和评分留出预算。** 输入编码也要保留任务所需的信息，奖励无法补回模型没有观察到的内容。报告没有单独测量这些设计带来的 RL 增益。

## 2. 通过测试以后，继续比较解法质量

MiMo 使用 GRPO（Group Relative Policy Optimization，组相对策略优化），从同题多次尝试的奖励差异中学习。这里的**优势（advantage）表示一条轨迹相对同组其他轨迹的好坏**：正优势鼓励其中的行为，负优势则压低这些行为的概率。

只用二元测试奖励时，同组所有轨迹都通过测试，优势就没有差异。即使成功、失败都有，成功解之间也得不到质量区分。GRS 和 GAR 分别针对这些情况补充评价，让模型继续学习更好的实现。

来源：§4.3、Eqs. (2)–(5)、Figures 7–8。

### 2.1 GRS 为成功解补充质量评分

GRS 先离线分析任务需求、仓库和已有尝试，形成实现与行为的评价标准；训练时再按这些标准逐条评分。它用于部分高通过率代码任务，使通过测试的轨迹仍能得到不同奖励。

</p>

*Figure 7，p.17。左侧改变奖励，右侧改变优势；用于不同代码子集，不是固定串行步骤。*

<div align="center">

| 机制 | 如何产生差异 | 适用范围 |
| :---: | :---: | :---: |
| **GRS** | 离线联合检查尝试、需求和仓库，形成实现与行为标准；在线逐条打分 | 部分高通过率任务，全过测组也可能继续学习 |
| **GAR** | 在线比较成败混合组，把更多正向权重分给更好的成功补丁 | 其余代码任务中的成败混合组 |

</div>

GRS 的奖励为：

```math
R_i=R_i^{\mathrm{test}}\,S_i^{\mathrm{sol}}\,S_i^{\mathrm{beh}}.
```

$`R_i^{\mathrm{test}}`$ 为二元测试分，$`S_i^{\mathrm{sol}}`$、$`S_i^{\mathrm{beh}}`$ 为实现和行为质量分。测试失败时奖励为零；通过以后，再比较边界处理、修改范围、仓库惯例和验证行为。

### 2.2 GAR 重新分配成功解的学习权重

GAR 保留二元成败奖励，调整的是成功解的学习权重。例如两条成功轨迹原本各有 +0.5 的优势，质量比较后可以调整为 +0.8、+0.2（未限幅示例）。更好的成功解得到更大权重，成功解的正优势总量仍保持不变。

来源：§4.3.2 Eq. (3)。设作弊审计修正后的二元奖励为 $`R_i`$，组均值为 $`\bar R`$，初始优势为 $`A_i=R_i-\bar R`$，成功集合为 $`\mathcal P=\{i:R_i=1\}`$。

具体做法是先乘质量因子 $`f_i\in(0,1]`$，降低较差成功解的权重，再统一缩放，使成功解的正优势总量恢复：

```math
\lambda=\frac{\sum_{j\in\mathcal P}A_j}
{\sum_{j\in\mathcal P}f_jA_j},
\qquad
A_i'=\begin{cases}
\lambda f_iA_i,&i\in\mathcal P,\\[0pt]
A_i,&i\notin\mathcal P.
\end{cases}
```

上式保留了成功解的正优势总量，同时改变它们的相对权重。实际实现还会限制缩放系数，再对成功、失败轨迹一起减去全组均值，使最终组均值为零；经过这些处理，总量未必仍守恒。评分器（grader）输出不可用时，则退回原优势。

GAR 需要组内有成功也有失败。全成功组的初始优势为零，仅靠重分配无法产生新差异，这也是它与 GRS 的区别。

> **关键 insight：质量评分让模型同时学习正确性和可维护性。** 报告观察到，没有在线评分时，更易出现吞异常、放宽验证和不必要的兼容分支。质量评价会减少对这些“能过测试、却不值得保留”的做法的鼓励，因此它也改变了训练目标。

> **关键 insight：评分计算可以提前分析任务，也可以在线比较新解法。** GRS 复用离线标准，GAR 比较当前生成的方案。由此推知，标准稳定的重复任务适合复用分析，新的策略则需要持续检查；报告没有测量两者的等成本效果或标准失效率。

### 2.4 长度约束以同题成功解为参照

快速失败的轨迹很短，却不能代表高效解法。MiMo 因此用**同题成功轨迹的长度**作参照，而且只有成功比例超过阈值时才施加惩罚。这样既能约束成功后的冗余，也给困难组保留探索空间。

示例（非报告配置）：参考长度为 10,000 tokens，允许超出 20%，则超过 12,000 才开始扣分；若扣满阈值设为 $`s=1`$，20,000 时扣满最大惩罚 $`X`$。报告未披露完整超参数，下面给出通用计算规则。

来源：§4.3.3 Eq. (4)。设成功集合为 $`\mathcal P_q`$，当通过率 $`\lvert\mathcal P_q\rvert/G\gt a_{\min}`$ 时，取成功生成长度的指定分位数：

```math
\ell_q^\star=\mathop{\mathrm{Quantile}}\nolimits_{B/100}
\{\ell_j:j\in\mathcal P_q\}.
```

```math
\widetilde R_i=R_i-\mathbf{1}[i\in\mathcal P_q]X
\left[
\mathop{\mathrm{clip}}\nolimits\left(
\frac{\ell_i/\ell_q^\star-1-\delta}{s-\delta},0,1
\right)
\right]^\gamma.
```

- $`\ell_i`$ 是当前轨迹的生成 token 数，$`B`$ 决定从成功解长度中取哪个分位数作为参照。
- $`X`$ 是最大扣分，$`\delta`$ 是允许超出参考长度的比例。
- $`s`$ 决定超出多少后扣满，$`\gamma`$ 控制扣分增长的曲线。

参数满足 $`s\gt\delta\geq0`$、$`X\geq0`$、$`\gamma\geq1`$。本文将原文通过率阈值 $`A`$ 改记为 $`a_{\min}`$，避免与优势混淆。未达到通过率门槛的组保留原奖励，调整后的奖励再用于计算优势。

### 2.5 对错误片段调整 token 优势

一条最终成功的轨迹，中途也可能调用不存在的工具，或使用错误的参数。如果整条轨迹都得到正向鼓励，这些错误也会被一起强化。MiMo 用规则标记错误片段，再调整对应 token 的优势：轨迹优势为正时取消对错误的鼓励，为负时加重对错误的惩罚。

来源：§4.3.3 Eq. (5)。令 $`h_{i,t}=1`$ 表示被规则标记，否则为 0：

```math
\widetilde A_{i,t}=\begin{cases}
\alpha(1-h_{i,t})A_i,&A_i\gt0,\\[0pt]
[\beta(1-h_{i,t})+\kappa h_{i,t}]A_i,&A_i\lt0,\\[0pt]
0,&A_i=0,
\end{cases}
\qquad \kappa\gt1.
```

三个系数分别处理不同情况：$`\kappa`$ 加重错误片段的负权重；$`\alpha`$ 将被取消的正向权重补给未标记 token；$`\beta`$ 则减轻未标记 token 的负权重，以抵消错误片段额外增加的惩罚。

判断依据是优势正负，而不是测试成败。质量或长度调整后，成功轨迹也可能具有负优势；规则没有标记的片段，也只是未检出错误。

为了尽量保持正、负两侧的优势总量，补偿系数按**整个训练 batch 中参与损失计算的 token**统计。设 $`H_+,H_-`$ 为正、负优势中被标记的 token 集合，$`C_+,C_-`$ 为未标记的集合：

```math
\alpha=\min\left(\alpha_{\max},
1+\frac{\sum_{(i,t)\in H_+}A_i}{\sum_{(i,t)\in C_+}A_i}\right),
\qquad
\beta=\max\left(\beta_{\min},
1-\frac{(\kappa-1)\sum_{(i,t)\in H_-}\lvert A_i\rvert}
{\sum_{(i,t)\in C_-}\lvert A_i\rvert}\right).
```

$`\alpha_{\max}\geq1`$ 限制正向放大，$`0\lt\beta_{\min}\leq1`$ 限制负权重减轻的程度。分母为零时相应系数设为 1。只有分母非零、未触发限制时，正负两侧的优势总量分别守恒；不保证最终梯度或策略熵不变。

> **关键 insight：轨迹的总体质量，不能说明其中每一步都值得鼓励。** GAR 仍给整条轨迹分配优势，局部规则才进一步处理错误动作。不过，这些规则只识别特定错误，没有测量每一步对成功的贡献；正优势轨迹中的错误也只是取消鼓励。

## 3. 验证器的准确性与稳定性

验证器要挡住作弊解，也要接受正确的替代实现。测试过严、强制匹配参考补丁的细节，同样会给模型错误的反馈。

来源：§4.2、Table 2、Figures 4–6。

<div align="center">

| 任务 | 核心验证方式 | 要避免的误判 |
| :---: | :---: | :---: |
| 代码 | 需求—测试对齐；每题 4 次尝试联合审计；有参考补丁时要求修复前后测试 8 次重跑稳定 | 强制参考实现的偶然细节，或漏掉需求 |
| 通用工作流 | 可重置 sandbox；代码查确定性状态，模型评审开放交付物 | 回复声称完成，实际文件或数据库不正确 |
| 视觉设计 | 开放设计逐件检查后同题比较；按图复刻主要查相似度 | 混用开放创作与明确参考的评价标准 |
| 漏洞复现 | 题面与验证来自同一错误报告，匹配漏洞类型和项目栈帧位置 | 将任意崩溃当成指定漏洞 |

</div>

代码测试分为两类：F2P（fail-to-pass，修复前失败、修复后通过）检查是否修好问题，P2P（pass-to-pass，前后均通过）检查是否引入回归。审计再将需求、补丁和执行记录放在一起，检查测试有没有遗漏要求或误拒正确实现。

重复执行检验的是稳定性，正确性还需要需求审计和反例。对通用任务，作者也用重复评审、不同模型评分器（judge）和对抗解修订标准，训练时由 MiMo-V2.6-SFT 评分。

> **关键 insight：误拒正确解，会削弱探索的收益。** 新的有效解法如果总被判失败，模型就可能继续学习与参考解接近的做法。审计正确替代解因此有助于保留探索的价值；这是机制上的推论，报告没有单独测量其收益。

报告记录了模型从新版包、上游仓库或 issue / PR 获取现成补丁的行为，而历史版本修复任务不允许使用这些信息。防御措施包括纠错示范、环境与缓存清理、网络隔离、训练前 hack agent 检查，以及训练中的持续审计。确认违规后，奖励归零，再重算组统计。

报告的“低于 2%”是检测出的违规占比，缺少漏检率，不能当成全部违规率。

> **关键 insight：模型变强以后，旧评分器也要重新检查。** 模型可能尝试过去没出现过的做法，或找到新的作弊途径。审计需要核对执行状态、补充针对性测试，并用对抗解检查漏洞；反复调用同一个 judge，未必能发现这些问题。

## 4. 采样、过滤与训练权重

预设的数据比例，要经过采样、过滤和损失计算才能变成实际的训练权重。这三步各自解决不同问题：调度负责收齐任务，过滤保留有奖励差异的组，损失聚合决定不同题目如何贡献更新。

来源：§4.1、§5.1、§6.2–6.3、Figures 15–16。

### 4.1 过滤会改变参与训练的题目

如果同题的尝试全部失败或全部成功，二元奖励就无法区分它们。只保留成功、失败都有的组时，过难和过易的题都会被大量过滤。

用一个简化模型说明：假设同题 16 次尝试相互独立，单次成功率均为 $`p`$，则保留概率为：

```math
P_{\mathrm{keep}}(p)=1-p^{16}-(1-p)^{16}.
```

成功率为 1% 或 99% 时，约 **14.9%** 的组被保留；50% 时约 **99.997%**。这不是 MiMo 实测：真实轨迹可能相关，奖励也可能连续。

> **关键 insight：动态过滤会形成随模型能力变化的训练课程。** 同一道题可能先是全失败，再有部分成功，最后全成功，参与训练的机会也随之改变。GRS 让部分全过测组继续比较质量；始终全失败的题则可能需要先补充示范或提高初始能力。

### 4.2 按耗时和保留率分配并发

不同来源的任务速度差别很大：25 个来源的平均生成 token 数相差 90 倍，平均耗时相差 66 倍。若统一分配并发，再按完成顺序收集 batch，快任务会占据更多份额。Sample Mixer 根据目标保留组数、过滤接受率、耗时和当前缺额分配并发，并提前为后续 batch 收集数据。

在固定收集速率下，慢任务和易被过滤的任务需要更多并发。需求大致随 **目标组数 × 耗时 ÷ 接受率** 增长；这里的接受率是过滤后保留的比例，并非任务成功率。例如，两源各需 100 组，一源接受率 0.5、耗时 10 分钟，另一源为 1、1 分钟，则并发需求约 **20:1**（解释性示例）。

</p>

*Figure 16，p.31。上排为收集进度，下排为占用份额。只按当前缺额调度容易频繁切换，只按长期目标调度则容易拉开收集进度；组合策略更平稳。模拟未包含训练、评分延迟、过期淘汰和回放，只比较调度效果。实际仅在启动 / 恢复首个收集步回放合格完整组。*

### 4.3 Prompt-mean 先在组内平均，再按题平均

把所有 token 合在一起平均，长题会因为 token 多而占据更大权重。**Prompt-mean 先算每道题轨迹组的平均损失，再对题目求平均**。例如，两题组长分别为 1 万、10 万 token，直接按 token 平均时权重约为 1:10；先按题归一化后，题目层面的名义权重为 1:1。

这只改变题目间的聚合方式。同题组内仍按 token 平均，因此各条轨迹并不等权；最终更新还取决于优势、概率比和哪些 token 被屏蔽。长度惩罚则另行计算。

来源：§4.1 Eq. (1)、§5.1。

```math
\mathcal{L}(\theta)
= -\mathbb{E}_{q\sim\bigcup_d\mathcal D_d,\;\{o_i\}_{i=1}^{G}\sim\mu_{\theta_{\mathrm{old}}}(\cdot\mid q)}
\left[
\frac{1}{\sum_{i=1}^{G}\lvert o_i\rvert}
\sum_{i=1}^{G}\sum_{t=1}^{\lvert o_i\rvert}
r_{i,t}M_{i,t}A_i
\log\pi_\theta(o_{i,t}\mid q,o_{i,\lt t})
\right].
```

上式先除以同题组的总 token 数，再在题目之间取平均。其余项分别控制学习方向、旧策略数据的权重，以及哪些 token 参与更新：

<div align="center">

| 符号 | 含义 |
| :---: | :---: |
| $`q`$、$`G`$ | 题目及每题轨迹数，本次 $`G=16`$ |
| $`o_{i,t}`$、$`o_{i,\lt t}`$ | 第 $`i`$ 条轨迹当前 token 及其之前的历史 |
| $`\pi_\theta`$、$`\mu_{\theta_{\mathrm{old}}}`$ | 当前训练策略、实际生成数据的策略 |
| $`A_i`$ | 轨迹优势；局部行为调整后替换为相应的逐 token 优势 |
| $`r_{i,t}`$ | 重要性采样权重 |
| $`M_{i,t}`$ | 屏蔽标记（mask），表示该 token 是否参与这项更新 |

</div>

报告列出代码 68%、通用工具 12%、视觉 13%、上下文遵循 3%、安全 4%；统计分母未说明，无法据此换算 token 或算力份额。

> **关键 insight：补齐来源数量以后，仍要检查来源内部的难度和权重。** 过滤会改变保留题目的难度分布，prompt-mean 则减少题目间的长度偏置。因此，分析训练收益还需要记录各来源的保留率、轨迹长度和有效更新权重。

### 4.4 组内固定 harness，组间更换配置

Harness 是模型执行任务时使用的框架，包括提示、工具接口、上下文管理和执行循环。MiMo 的 mini-harness 在**同题组内保持配置相同，不同组之间更换配置**：组内比较尽量只反映行为差异，组间变化则训练模型适应不同接口。

在训练时未使用的 Codex、Claude Code、mini-swe-agent 上，DeepSWE 平均 Pass@1 约从 50% 升至 66%。这支持跨接口迁移，但报告没有等预算的单框架对照（§4.2.5、Figure 10）。

> **关键 insight：只奖励任务完成，模型可能忽略流程要求。** 作者指出，生产 harness 的保护规则和流程要求未必计入奖励。需要模型遵守的规则，应进入监督或由执行系统保证；benchmark 成绩提高，并没有验证这些规则已经学会。

## 5. 概率计算、专家负载与训练配置

训练要比较当前策略与生成数据时的策略，才能调整旧数据的学习权重。但即使模型参数相同，不同引擎也可能选择不同的专家、算出不同的采样概率。MiMo 需要先对齐这些执行条件，再计算概率比。

来源：§4.1、§5.1、§5.4–5.5、§6.4、Figure 11。

### 5.1 保存生成时的概率，重放采样条件

MiMo 对每个 token 计算重要性采样权重：用当前训练策略给它的概率，除以生成时实际使用的概率。分母必须在生成时保存。

这是因为 partial rollout 会暂停并续跑未完成的轨迹。续跑前模型可能已经更新，同一条轨迹的不同片段因而可能来自不同版本，无法事后用一个旧版本统一补算分母。

```math
r_{i,t}
=\mathop{\mathrm{sg}}\nolimits\left[
\frac{\pi_\theta(o_{i,t}\mid q,o_{i,\lt t})}
{\mu_{\theta_{\mathrm{old}}}(o_{i,t}\mid q,o_{i,\lt t})}
\right].
```

$`\mathop{\mathrm{sg}}\nolimits`$ 表示停止梯度：ratio 仅作权重，梯度经 log-probability 项传播。

生成侧 SGLang 与训练侧 Megatron-LM 还需三层对齐：

<div align="center">

| 层次 | 处理 | 对齐对象 |
| :---: | :---: | :---: |
| 权重 | QDQ（quantize–dequantize，量化再反量化）遵循 MXFP4 生成内核 | 实际数值 |
| 专家路径 | R3（Rollout Routing Replay，生成路由重放） | 生成时的专家选择 |
| 截断采样 | 重放 top-k / top-p 候选集并在其中归一化 | 实际采样分布 |

</div>

截断采样会先筛出候选 token，再在候选集内归一化。例如，某 token 在全词表中的概率为 0.2，保留候选集的总概率为 0.8，实际采样概率就变成 0.25。训练侧若拿截断前的概率作分子，0.2 / 0.25 得到 0.8，便会出现**策略没变，ratio 却变了**的情况（解释性示例）。

因此，训练侧不仅要保存生成时选中 token 的概率，还要知道当时保留了哪些候选，才能按相同范围计算分子。

来源：§6.4。下式是对报告归一化机制的数学表达。生成时保留候选集为 $`S_t`$，训练用同一集合归一化：

```math
\pi_\theta^{S_t}(y\mid h_t)=
\frac{\pi_\theta(y\mid h_t)}{\sum_{v\in S_t}\pi_\theta(v\mid h_t)},
\qquad y\in S_t.
```

$`h_t`$ 为当前历史，$`y`$ 为采样 token。分母将同一候选集中的概率加起来，使训练侧也得到候选集内的概率。

实现先用覆盖全词表的固定形状位图，将候选集从 GPU 传到 CPU，再使用稀疏存储，避免变长同步或传输时截断候选集。报告中典型 top-p=0.97 时，平均候选数小于 5。

> **关键 insight：概率比应反映策略变化，而不是训练、生成引擎的差别。** 路径和候选集重放为此提供了对齐条件。不过，逐 token ratio 只校正“已经到达这段历史以后，如何选择下一个 token”，没有校正到达这段历史的概率。它仍不是对旧轨迹偏差的完整校正。

### 5.2 正、负优势分别控制概率比范围

来源：§5.1。

生成时的策略与当前策略差异较大时，概率比可能过大或过小，MiMo 会屏蔽这些 token。由于正、负优势对应不同的更新方向，两者分别设置上下界：

```math
M_{i,t}^{\mathrm{clip}}=
\mathbf{1}\left[
(A_i\geq0\land\epsilon_+^{l}\leq r_{i,t}\leq\epsilon_+^{h})
\lor
(A_i\lt0\land\epsilon_-^{l}\leq r_{i,t}\leq\epsilon_-^{h})
\right].
```

两组初始区间均为 **[0.2, 5.0]**。越界 token 直接被屏蔽。例如 ratio 为 6 时，该 token 不参与这项更新，而不是把 ratio 截成 5；这与标准 PPO 的 `min(unclipped, clipped)` 目标不同。

MiMo 还根据输出分布的熵调整范围，熵用于衡量选择的多样性。熵过低时放宽正区间、收窄负区间，熵过高时反向调节，并分别监控被屏蔽的 token 比例。

报告未披露完整控制器，也未在该目标中写出参考模型 KL 惩罚或默认优势标准差归一化。复现时需要按已披露的目标实现，不能直接套用常见的 GRPO 配方。

</p>

*Figure 11，p.24。三栏为负载变异系数、最大值 / 均值、冷专家占比；越高越不均衡。橙线可训练，蓝线冻结。*

Pro 第 9 层的 384 个专家，在 router 可训练的前 20 步，负载变异系数由 0.78 增至 2.0，峰值负载由均值的 6 倍增至 16 倍，冷专家占比由 0.5% 增至 22%；冻结时基本稳定。

### 5.4 轨迹增长时的容量与推测解码配置

Partial rollout 收齐一个 batch 后，先暂停仍在执行的长任务，更新模型，再恢复任务，从而减少等待长轨迹的时间。代价是模型更新后要重新读取历史，重建 KV cache（历史 token 的 key / value 缓存），这称为 re-prefill。它消耗计算，却没有增加新的探索。

同一模型版本内可以复用缓存，等待工具时也可将状态移至主机内存。因此，batch 大小、并发数量和续跑频率要一起选择，才能兼顾等待时间与重算开销。

负载估计也容易受已完成样本误导：短轨迹先完成，会使早期长度估计偏低；同源不同 harness 的长度又相差超过两倍。即使全 batch 的专家负载均衡，局部专家 rank（负责一组专家的并行进程）仍可能接收均值 30 倍以上的 token。Flash 后期轨迹增长，还曾导致单节点打包内存耗尽。

DFlash 用小模型提出候选 token，再由主干并行验证。它先在 SFT 策略上训练，再用匹配 RL 任务配比的早期轨迹适配；RL 默认 block-6。（来源：§6.4。）

<div align="center">

| 比较 | 报告结果 |
| :---: | :---: |
| block-6 相比原 MTP 配置 | 平均接受长度高 31.3% |
| 混合 RL 中 block-6 相比 block-8 | 全局平均吞吐高约 6%，接受长度变化很小 |
| 所测长上下文负载下，RL 适配的 FP8 DFlash 相比基线 | 每节点吞吐高约 10.3% |

</div>

草稿模型提出更多候选，也会增加主干的验证工作。因此，选择 DFlash 配置要看实际吞吐，不能只看平均接受长度。表中三项比较的基线不同，增益不能相加。

> **关键 insight：训练中的轨迹变长以后，原来的容量估计可能失效。** 要把未完成的长任务和局部专家峰值算进去。推测解码也要看端到端吞吐：接受更多候选 token 会增加验证工作，单看接受率或平均负载容易选错配置。

### 5.5 Muown 与 RL 初始化

报告观察到，AdamW 随混合 RL batch 增大而优化效率递减，因此提前在 Mid-training 切换了优化器。隐藏权重矩阵使用 Muown，Embedding、输出层和 router 继续用 AdamW。

Muown 是 Muon 的变体，用显式行范数控制减轻谱范数漂移和对权重衰减的敏感性。作者记录的这次切换没有损失突增（§3.2；[Muown 论文](https://arxiv.org/abs/2605.10797)）。

来源：§5.1。

<div align="center">

| 项目 | 报告配置 |
| :---: | :---: |
| 优化器 | Muown |
| Learning rate | $`3\times10^{-6}`$ |
| Weight decay / LR warmup | 均不使用 |
| Gradient clipping | 1.0 |
| Muon momentum | 0.95，启用 Nesterov |
| Newton–Schulz iterations | 10 |
| 额外 update scaling | 0.5 |
| Adam 部分 | $`\beta_1=\beta_2=0.95`$，$`\epsilon=10^{-8}`$ |
| RL 初始化 | 继承 SFT 的 FP32 master weights 与 Muown row state |
| MoE router | 冻结 |

</div>

> **关键 insight：复现 RL 还需要优化器状态。** 报告从 SFT 继承 FP32 主权重和 Muown 行状态，并沿用低精度执行方式。只加载部署权重，会遗漏这些训练条件。

## 6. MOPD2 的完整轨迹与前缀蒸馏

学生自行执行多轮以后，可能进入教师训练时较少覆盖的历史，教师的指导也可能失准。MOPD2 因此保留两种练习：学生从头完成任务，或从教师、示范的中途历史开始，只生成当前一轮。

教师也有两类：可验证任务用混合任务 RL 训练领域教师；难以可靠评分的开放领域任务，则用高质量合成示范训练 SFT 教师。

来源：§5.6、Figure 13、§6.2。

<p align="center">

<div align="center">

| 路径 | 学生从哪里生成 | 监督来源 |
| :---: | :---: | :---: |
| Standard MOPD | 从任务起点自主完成整条轨迹 | 可验证任务上的 RL 领域教师 |
| Teacher-Prefix OPD | 教师轨迹某轮前的完整历史，续写一轮 | RL 领域教师逐 token 指导 |
| SFT-Prefix OPD | 示范某轮前的完整历史，续写一轮 | 高质量合成示范训练的 SFT 教师逐 token 指导 |

</div>

一条含 $`k`$ 轮模型回答（assistant turns）的源轨迹，可以拆成 $`k`$ 个前缀，每个前缀都包含对应轮之前的完整历史。学生从这里生成当前轮，预先分配的教师再根据同一历史和学生已生成的 token，提供逐 token 监督。示范提供的是历史上下文，学生不必照抄示范中的续写。

例如，学生从“已读完仓库、准备修改”的前缀开始，练习的是接下来如何修改，并没有练习前面的仓库阅读过程（示例）。**这里的 on-policy 只覆盖新续写，前缀历史来自外部。**

> **关键 insight：从可靠前缀续写，只训练了任务中的一部分。** 学生可以反复练习当前步骤，并减少教师指导失准；从任务开始规划、执行和连续纠错，仍需要完整 rollout（从头执行任务）。因此，单轮蒸馏的效果与任务自主完成能力应分开评测。

前缀路径没有独立消融，教师名单、学生初始化和损失配置也未完整披露。报告尝试向游戏开发、科研、具身智能等难验证领域扩展，但任务、评分器和教师仍由外部建设。模型在这些评价下进步，尚未展示它能自行改进任务、评价和训练流程。

### 7.3 开源数据中的评分标准与环境信息

[官方开源数据](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss)有 **7,780 条任务**，并提供[训练代码](https://github.com/XiaomiMiMo/verl/tree/mimo-oss)和[环境镜像](https://hub.docker.com/r/xiaomimimo/mimo-v2.6-rl-oss)。本仓库固定版本分析发现：

* 925 条通用工作任务中，**94.4% 的评分正文比题面长，长度比中位数为 2.33 倍**。标准保存了排除失效记录、合并别名、处理资料冲突等领域判断；长度不保证质量，答案材料须与 agent 输入隔离。
* 5,125 个评分条目中，4,437 项标为模型评审，顶层却统一为 `rule`。**可验证不等于确定性程序评分**，复现还依赖 judge 版本和证据读取方式。
* 1,000 条安全记录对应 693 种题面、1,000 个镜像名。文本去重会漏掉环境差异；镜像不同也不能证明漏洞独立。

> **关键 insight：复现一条任务，需要同时固定题目、环境和评分方式。** 评分标准可能包含题面没写出的领域判断，环境则决定哪些操作能执行、哪些证据能读取。只按题面去重，或仅凭 `rule` 字段选择评分器，都可能改掉原来的训练条件。

以上是版本 `639865f` 的开源数据审计，不代表内部训练统计。长度按字符计算，排除 JSON 与验证代码，见[结果](data/MiMoV2.6-RL-oss-summary.json)和[脚本](../../scripts/analyze-mimo-rl.py)。

开源代码对应小模型实验：默认 batch 64、每题 16 条、256K 上限，工具错误惩罚关闭。这些配置不能作为 Pro / Flash 的内部配方（[固定版本脚本](https://github.com/XiaomiMiMo/verl/blob/a2ad9f6160b03ff2d47e59832bfb6b289f37c917/scripts/code/train.sh)，2026-09-29 核对）。

> **关键 insight：继续研究这套方法，可以先补三组对照。**
>
> - 固定训练预算，比较探索与评分各增加了多少有效学习信号。
> - 固定解题预算，检查质量提升是否仍然存在。
> - 分别在学生自主生成的历史和可靠前缀上，评测教师的指导效果。
>
> 这些比较能帮助分清收益来源，报告尚未完整给出。
